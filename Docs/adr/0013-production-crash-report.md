# ADR 0013: Production Crash Report

## Status

Accepted.

## Decision

Motivation Blues stores the latest route crash report locally in browser storage and exposes a copy action from the `ErrorBoundary` fallback.

The report is generated by `src/lib/crashReport.ts` when React calls `componentDidCatch`. It includes:

- app version, build SHA, Vite mode, and base URL;
- active route/view;
- local/cloud mode, cloud error summary, Telegram launch flag, and outbox counters;
- sanitized URL path/query-key summary, online state, user agent, language, and viewport;
- error name, message, stack, and React component stack.

The report intentionally excludes user email, post content, draft content, bank content, editor buffer content, query/hash values, Supabase tokens, and service-role credentials.

## Context

The route-level `ErrorBoundary` prevents a blank page, but production debugging still needed concrete diagnostics. Hosted telemetry would add privacy, consent, network, and vendor concerns. Since the app already follows local-first safety rules, the first diagnostic step should be local-only and user-controlled.

## Consequences

- Production users can copy a report after a crash.
- Debugging route crashes becomes less dependent on screenshots.
- No automatic external error collection exists.
- localStorage can be unavailable in restrictive browser modes, so report storage must never block fallback rendering.
- Event-handler and async errors still need explicit local handling if they become recurring issues.

## Verification

- Unit tests cover report creation, storage, malformed reads, and clipboard copy.
- Playwright route crash smoke verifies local report creation, copy action, navigation recovery, and editor buffer survival.
- `npm run quality`.
- `npm run test:e2e`.
- `npm run verify:pages`.
